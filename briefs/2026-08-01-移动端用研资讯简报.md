### [AgentHands: Generating Interactive Hand Gestures for Spatially Grounded Agent Conversations in XR]
**来源**：Google Research / Google XR Labs（CHI ’26；Ziyi Liu, David Li, Zhongyi Zhou, David Kim, Ruofei Du, Xun Qian）  
**类型**：方法论  
**是否与动效相关**：是（共话语手势动画 / GestureEvents 时序编舞 / 空间锚定运动）

**摘要**：针对「语音/文本无法承载空间指令」的心智映射缺口，提出 LLM 驱动的 XR Agent 手部表达系统：用形成性 taxonomy 约束手势库，再以词对齐的 GestureEvents 驱动参数化动画引擎。N=12 对照显示，相比纯语音基线，跟随时空任务更清晰、参与感更高。对掌握移动端动效的价值是：把「运动」写成可调度语义事件，而不是事后加的装饰层。

**详细展开**  
- **背景与问题**：手机助手已能感知上下文（货架对比、博物馆讲解），但仍用长段文字描述「按钮在机器背面」一类空间操作，迫使用户自行完成抽象→具体映射；UI 箭头/面板能指位置，却缺少确认、警示、鼓励等社会线索，也难与流式 LLM 回复同步。  
- **主要发现/方法/功能/观点**：形成性研究（N=10）提炼多维 taxonomy → 手势库与组合规则 → meta-instruction 让回复内嵌 GestureEvent（类型+参数，对齐触发词）→ runtime 解析为时间戳姿态驱动动画；并借助场景理解做物体级空间锚定（指向气根、倾倒浇水壶、就地比划 30cm 等）。CHI ’26 论文与 Google Research 摘要页公开。  
- **对移动端用研或 AI 产品经理的启示（含动效）**：移动端 Agent 可先借「屏幕内手势/光标轨迹/高亮路径」迁移同一套事件模型：关键动作 = 强运动对比 + 词级同步；次要确认 = 弱 beat。用研脚本可测「空间任务错误率 / 回看说明次数 / 主观清晰度」。Reduce Motion：保留指向与高亮，去掉表演性 overshoot 与交互 high-five。  
- **原文链接**：https://research.google/pubs/agenthands-generating-interactive-hands-gestures-for-spatially-grounded-agent-conversations-in-xr/（ACM：https://doi.org/10.1145/3772318.3790938 ；CHI 节目单：https://programs.sigchi.org/chi/2026/program/content/222723）

### [Self-Evolving Systems: Moving Beyond Deterministic Interfaces to Adaptive Generative Interfaces]
**来源**：Google Research（2026；Adaptive Generative Interfaces / Penny 银行原型）  
**类型**：方法论  
**是否与动效相关**：是（运行时界面 morph / 视觉与功能属性实时重构）

**摘要**：提出「自演化系统」：界面不再只是预装功能集合，而是按用户即时意图在运行时扩展能力。机制分三类——Directed synthesis、Inferred synthesis、Real-time adaptation。N=72 拉丁方对照中，自适应生成版 SUS 84.38 vs 确定性版 53.96（Δ30.42，p<0.0001，d=1.04）。对动效学习的启示是：生成 UI 的可用性高度依赖「变化如何被看见」——morph 与重组转场是降低导航税的一部分。

**详细展开**  
- **背景与问题**：现代工作流复杂度已超过固定信息架构可承载的导航税；静态菜单与层层钻取让用户付出持续寻路成本。  
- **主要发现/方法/功能/观点**：Penny 数字银行原型上比较确定性界面与自适应生成界面；客观屏录核验任务表现，SUS 量化可用性；结论呼吁设计师从「画固定屏」转向「System Builders」——定义原则与规则，让界面生长。Google Research 公开摘要页标注 2026。  
- **对移动端用研或 AI 产品经理的启示（含动效）**：评测 GenUI/Agent 产物时，除功能正确性外，单列「变化可理解性」：新控件从哪来、旧控件去哪、关键 CTA 是否用更强 Spatial 运动对比。动效 token 建议：`intent_shift` → 可打断 spring 重组；`feature_spawn` → Shared Element 或短 morph；`inferred` 变更需二次确认节奏。Reduce Motion：用静态分区高亮 + 文案差分替代位移。  
- **原文链接**：https://research.google/pubs/self-evolving-systems-moving-beyond-deterministic-interfaces-to-adaptive-generative-interfaces/

### [60fps MCP：让 AI 按真实交互配方写动效]
**来源**：60fps.design（MCP Beta；页面时间戳 2026-07-31 UTC）  
**类型**：工具  
**是否与动效相关**：是（动效检索 / 运动拆解 / SwiftUI 代码生成）

**摘要**：面向 Cursor / Claude / ChatGPT 等 MCP 客户端，把「真实 App 交互镜头」变成可调用工具：搜 shot、取关键帧与情绪、拆 Trigger→Start→Move→Settle、输出经编译检查的 SwiftUI。口号是「Your AI can build UI. It can’t do motion」——用参考配方替代模型瞎猜时长与弹簧。

**详细展开**  
- **背景与问题**：Agent 写界面时常输出通用 fade；缺少可复用的节奏、落点与触发语义，导致动效方言不一致。  
- **主要功能/观点**：五类工具：`search_shots`、`get_shot`、`get_motion_breakdown`、`get_motion_code`、`get_related_shots`；支持自然语言找参考（如「finance app 的冷静转场」「弹簧下拉刷新」）。需 60fps PRO license；Apps/Editors 两种接入方式。  
- **对移动端用研或 AI 产品经理的启示（含动效）**：用研/设计可把「镜头 ID + 四段拆解」写进动效验收单；PM 评审时要求 Agent 贴出 Settle 时长与 Reduced Motion 回退，而不是只看 GIF。适合与 M3 Expressive / Apple 流体方言对照建 token 表。  
- **原文链接**：https://60fps.design/mcp

### [Family Continuity Interaction]
**来源**：60fps.design / Family（钱包 App；页面时间戳 2026-07-31 UTC）  
**类型**：案例研究  
**是否与动效相关**：是（Shared Element Morph / Onboarding 连续体 / 弹簧物理）

**摘要**：在「添加已有钱包」流程中，顶部大型钱包插画在用户选择 Watch 等选项后缩小、变形并直接过渡为下一步文本输入容器；键盘同步上滑，其余元素以 spring 淡出滑移。示范如何用共享元素把多步 onboarding 收成一条空间叙事，降低上下文切换成本。

**详细展开**  
- **背景与问题**：多步设置若每屏硬切，用户会丢失「我在完成哪件事」的空间记忆。  
- **主要功能/观点**：标签含 Shared Element、Morph、Spring Physics、Onboarding、Input；插画→输入框的连续变形是注意力锚点，键盘与附属 UI 作为伴随运动。  
- **动效启示（快速掌握）**：Hero 元素全程保留同一视觉身份；次要控件只做短 fade/slide。总时长压在一次扫视内。Reduce Motion：跳过 morph，保留静态插画缩略 + 输入框出现。来源为展示站，无对照实验。  
- **原文链接**：https://60fps.design/shots/family-continuity-interaction

### [Duolingo Tap Chest Open Card Spin Interaction]
**来源**：60fps.design / Duolingo（页面时间戳 2026-07-31 UTC）  
**类型**：案例研究  
**是否与动效相关**：是（奖励序列 / 弹簧稀有度升级 / 卡片旋转揭示）

**摘要**：点击升级/开箱时，宝箱以 bouncy spring 扩张闪烁，稀有度从 Common→Rare；开箱触发粒子闪光与盖子弹开，奖励卡依次旋转放大入场；点卡前进下一奖励后平滑回到学习地图。适合学习「高价值奖励」如何用分段弹簧 + 序列揭示维持可控节奏。

**详细展开**  
- **背景与问题**：奖励动效若一次播完所有信息，用户既跟不上稀有度变化，也无法建立「我触发了升级」的因果感。  
- **主要功能/观点**：Upgrade bounce → Open particles → Card spin sequence → Map return；标签含 Spring Physics、Gamification、Reward、Sequence、3D。  
- **动效启示**：把奖励拆成「状态升级确认 / 不可逆开箱 / 逐卡结算」三拍；每拍 settle 可读后再进下一拍。Reduce Motion：静态徽章升级 + 卡片列表淡入，去掉旋转与粒子循环。  
- **原文链接**：https://60fps.design/shots/duolingo-tap-chest-open-card-spin-interaction

### [Smartphone UI Design Trends for 2026: What’s Really Changing and Who’s Doing It Best]
**来源**：Tech in Deep（综合横评；iOS 26 / One UI 8.5 / HyperOS 2）  
**类型**：移动设备竞品分析  
**是否与动效相关**：是（系统动画重建 / Liquid Glass 材质运动 / 手势导航与触觉）

**摘要**：把 2026 旗舰系统拆成三条哲学：Apple Liquid Glass 全系统半透明材质（观感强、强光对比受质疑）；Samsung One UI 8.5 侧重 AI 与可定制而非视觉翻新；Xiaomi HyperOS 2 重做系统动画（锁屏→主屏 fade+zoom、通知栏角向飞入），在旗舰 SoC 上累积为「够贵」的流体感。手势导航成为跨平台默认输入，触觉是手势信心的隐形引擎。

**详细展开**  
- **背景与问题**：用户常把「玻璃好看」与「动画顺滑」混为一谈，竞品结论容易被演示场景（咖啡店柔光）绑架。  
- **主要发现/方法/功能/观点**：文内对比表覆盖视觉、AI、定制、手势默认值与无访问性；指出 Samsung 仍常默认三键导航；HyperOS 动画「逐条看小、合起来像旗舰」。属媒体体验评论，非实验室帧率对照。  
- **对移动端用研或 AI 产品经理的启示（含动效）**：竞品脚本分轨记录——材质对比（室内/强光）、转场主观流畅、手势默认与可发现性、Reduce Transparency 后的任务耗时。动效策略上，系统级一致性（全链路同一物理方言）比单条「更弹」更重要；AI 主动层出现时要用弱打扰运动，避免与系统转场抢层级。  
- **原文链接**：https://www.techindeep.com/smartphone-ui-design-trends-for-2026-76683

### [No New Name Has Replaced “UX”]
**来源**：Nielsen Norman Group / Rachel Banawa（2026-07-31）  
**类型**：专家观点/动态  
**是否与动效相关**：否

**摘要**：专家相关（Kate Moran 常驻机构 NN/g）。对 604 名科技/设计从业者做间接命名调查：给出 UX 工作定义但不提「UX」一词，请对方命名该领域。70% 回答含 UX 相关关键词；「experience design」「human-centered design」等替代词自发出现率极低。结论：当下不宜指望改名解决价值证明难题，应把贡献连到决策、结果与风险。

**详细展开**  
- **背景与问题**：裁员与预算压力下，行业反复讨论是否该弃用「UX」；同时 AI 与研究民主化模糊了角色边界。  
- **主要发现/方法/功能/观点**：间接提问降低「追潮流标签」偏差；角色影响用语（产品经理更爱说 product）。局限：样本偏 NN/g 触达人群、地理代表性不足。  
- **对移动端用研或 AI 产品经理的启示**：对内沟通少纠结头衔，多交付「动效/交互决策避免了什么风险」（如误触、空间误解、可访问性对比失败）。与本期 Google 方法论并列时：用研价值要用任务指标与 SUS/错误率说话，而不是新名词。  
- **原文链接**：https://www.nngroup.com/articles/no-new-name-ux/

### [拆了腾讯 WorkBuddy，我发现了 AI 产品三个值得抄的设计]
**来源**：人人都是产品经理 / Amber（2026-07-31）  
**类型**：专家观点/动态  
**是否与动效相关**：否（弱相关：多 Agent 评审切换与进度态可用运动层级表达，但原文焦点在架构）

**摘要**：专家相关（黄钊 / hanniman 等 AI PM 常驻平台「人人都是产品经理」）。实测拆解 WorkBuddy：表面是聊天框，实为助理→项目→自动化三层成熟度路径；底层是路由 + Skill 市场而非经典主从多 Agent；多 Agent 真实价值在评审阶段交叉校验，而非创作阶段全员并行。竞争从模型能力转向工作流嵌入深度与资产沉淀。

**详细展开**  
- **背景与问题**：效率类 AI 产品 DAU 数字刷屏后，难分辨营销话术与可迁移设计决策。  
- **主要发现/方法/功能/观点**：对照腾讯云文档验证路由/SkillHub/MCP/沙箱等；创作单 Agent 保上下文，评审切多专家 Agent；护城河在 Skills/SOP/连接器配置等组织资产。  
- **对移动端用研或 AI 产品经理的启示**：移动端 Agent 产品可复用「信任递进三模式」；用研观测用户何时愿意从一问一答切到可监督的项目时间线（可接上期 Plover 计划外置思路）。若补动效：模式切换用明确 Spatial 方言区分助理/项目/自动化，避免三模式共用同一转场导致心智混淆。  
- **原文链接**：https://www.woshipm.com/ai/6436781.html
