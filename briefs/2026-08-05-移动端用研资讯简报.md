### [Benchmarking Living-Screen-Native GUI Agents on Short-Video Platforms]
**来源**：北京理工大学 / 清华大学 / 北京航空航天大学（Yao, Huang, Wu 等；arXiv:2606.04701）  
**类型**：方法论  
**是否与动效相关**：是（连续时间活屏幕 / 短视频自动播放与 GUI 共渲染 / watch·wait 观察动作）

**摘要**：论文指出主流 GUI Agent 默认「动作之间屏幕冻结」，无法描述短视频等信息持续流动的移动界面。作者形式化 Living-Screen-Native Agent：环境自主演化，且 Agent 必须主动决定观察哪一段视觉切片；并发布 LivingScreen 基准（浏览器复刻短视频 App + 三层任务 + 准确率与信息效率联合指标）。对掌握移动端动效的价值是：把「播放中的运动内容」与「静态控件动效」拆开评测——Agent/用研都要回答「看多久才够」。

**详细展开**  
- **背景与问题**：Video QA 给离线视频文件，GUI 基准给静态截图序列；短视频真实体验是自动播放 + 评论/进度条/侧栏共渲染，人会主动决定刷过、seek、展开评论或继续看。  
- **主要发现/方法/功能/观点**：动作空间除 click/swipe/type 外，新增 `watch`（按时长与帧率录屏）与 `wait`（让画面自行流动）。任务分 L1 原子 GUI、L2 跨源理解、L3 闭环应用。前沿 MLLM 均未达到人类的成本—准确率权衡；主导失败模式是 over-/under-observation（看太多或太少），被作者定义为未来 GUI Agent 新能力轴。代码与数据见 GitHub `BITHLP/LivingScreen`。  
- **对移动端用研或 AI 产品经理的启示（含动效）**：短视频/直播类产品做 Agent 或自动化用研时，协议不要只截「暂停瞬间」：应记录观察预算（秒数、是否 seek、是否读评论）。界面动效侧：进度条 scrub、评论抽屉展开、双击点赞等状态变化要有可感知的内容差分，便于人与 Agent 校准「信息是否已获取」。Reduce Motion 下保留进度与文案状态，弱化装饰性循环播放特效。  
- **原文链接**：https://arxiv.org/abs/2606.04701（HTML：https://arxiv.org/html/2606.04701；代码：https://github.com/BITHLP/LivingScreen）

### [Toward Natural and Companionable Virtual Agents via Cross-Temporal Emotional Modeling]
**来源**：Microsoft Research（Zheng, Qin, Li, Huang 等；CHI 2026；arXiv:2605.15812）  
**类型**：方法论  
**是否与动效相关**：否（跨时情感状态与行为闭环；非界面过渡动画，但对「表达节奏/长期一致性」有产品启示）

**摘要**：MSR 在 CHI 2026 提出 CTEM（Cross-Temporal Emotion Modeling）：针对陪伴型 Agent「片段感强、情感不连贯」问题，把长期行为史与瞬时情感表达连成闭环——经历更新情绪状态，情绪再调制当下行为，用户反馈回写记忆与状态。实例化产品 Auri（即时通讯陪伴 Agent），21 天野外研究（N=96，18–26 岁）报告自然度、连贯性与情感和谐度提升。

**详细展开**  
- **背景与问题**：基础模型已能对话，但长期陪伴仍常像「每次重开」：行为很少改变内部情绪，情绪也很少约束后续行为。  
- **主要发现/方法/功能/观点**：CTEM 含心理依据的行为池动态生成、随时间演化的情绪/人格/历史记忆、多模态自适应交互。每个时间步生成行为清单，按当前情绪执行其一，再据结果与反馈更新状态。野外研究结合日志、问卷、访谈与计算指标。  
- **对移动端用研或 AI 产品经理的启示**：移动陪伴/助理产品可用「跨会话一致性」量表替代单轮满意度：用户是否感到「它记得上次为什么低落/兴奋」。界面表达上，情绪变化应用可审计的文本/状态标签承载，不宜只靠微妙视觉微动效；用研可测「情绪表达强度」与「可纠正/可遗忘」控件是否降低「被冒犯」感。与本期 woshipm「持续学习」条目可交叉：记忆治理是 CTEM 落地的产品层。  
- **原文链接**：https://www.microsoft.com/en-us/research/publication/toward-natural-and-companionable-virtual-agents-via-cross-temporal-emotional-modeling/（ACM：https://doi.org/10.1145/3772318.3790917 ；arXiv：https://arxiv.org/abs/2605.15812）

### [CineMobile: On-Device Image-to-Video Diffusion for Cinematic Camera Motion Generation]
**来源**：上海交通大学 / 南开大学 / 传音（Huang, Deng, Wang, Xiao, Deng；arXiv:2607.03803；2026-07-04）  
**类型**：工具  
**是否与动效相关**：是（端侧电影运镜 I2V / bullet time·dolly zoom·slow motion / 4-step 蒸馏与量化）

**摘要**：面向手机端「图生视频 + 可控镜头运动」需求，CineMobile 在 Wan2.1 系 DiT 上做剪枝、4 步蒸馏与混合精度量化，把模型压到约 1GB 内，相对教师模型约 40× 加速；在 MediaTek Dimensity 8400 Ultimate 上报单步去噪约 20s、峰值显存约 1.8GB。对快速掌握移动端动效的借鉴点：把「运镜方言」当成可产品化的 motion preset，而不是开放式文生视频。

**详细展开**  
- **背景与问题**：高质量 DiT 视频生成参数大、步数多，手机端难部署；激进加速又易伤语义与主体一致性。作者收窄到结构清晰的电影镜头效果，以提高可控性与可评估性。  
- **主要发现/方法/功能/观点**：深度方向结构化剪枝保隐层宽度 → SFT warm-up 适配运镜分布 → AdvDMD 风格对抗/RL 蒸馏到 4 步 → FFN 4bit + 其余 8bit。VBench 与人类评估上，三类运镜总分接近教师模型。  
- **对快速掌握移动端动效的启示**：内容创作/相机类 App 可先交付 3～5 个「可命名运镜 token」（环绕、推拉变焦、慢门），用研测可理解性与等待容忍（端侧仍可能数十秒级）。UI 侧用进度分段 + 可取消，避免无限循环装饰；生成完成后用短 shared-element 过渡把静帧衔接到成片，减少「黑盒转圈」。注意：论文偏生成管线性能，不等于系统级 UI 过渡规范。  
- **原文链接**：https://arxiv.org/abs/2607.03803（HTML：https://arxiv.org/html/2607.03803）

### [Roll Camera 3D Film Box Open Interaction]
**来源**：60fps.design / Roll Camera（页面收录时间戳 2026-08-04 UTC）  
**类型**：案例研究  
**是否与动效相关**：是（3D 开箱 / skeuomorphic 胶卷罐 / Load Film 落入快门）

**摘要**：点击 Unbox Filter 后，3D 胶卷盒顶盖弹开，过渡到可交互的漂浮胶卷罐与滤镜参数；再点 Load Film，罐体缩小落入快门并直接打开相机。示范「开箱奖励 → 装载确认 → 进入创作」的三段式空间叙事，适合学习 skeuomorphic 动效如何服务状态机而非纯装饰。

**详细展开**  
- **背景与问题**：滤镜/道具解锁若只弹 Toast，缺少「获得感」；若全程华丽循环，又耽误开拍。  
- **主要功能/观点**：第一段开箱完成拥有；第二段展示规格供扫读；第三段 Load 把资产写入相机状态并切场景。标签含 3D / Reveal / Reward / Skeuomorphic / Gamification。  
- **对快速掌握移动端动效的启示**：把道具获取写成 `unbox → inspect → commit` 三拍，每拍只改一个信息层级；`commit` 必须落到真实功能态（滤镜已启用）。用研可测：用户是否在开箱高潮后仍读懂参数，以及 Load 是否被理解为不可逆。真机注意 3D 掉帧；Reduce Motion 可改为静态开箱图 + 明确「已装载」文案。展示站无 A/B 转化数据。  
- **原文链接**：https://60fps.design/shots/roll-camera-3d-film-box-open-interaction

### [Picky Card Scan Sort Interaction]
**来源**：60fps.design / Picky（页面收录时间戳 2026-08-04 UTC）  
**类型**：案例研究  
**是否与动效相关**：是（拍立得卡堆 shuffle / 扫描 loading / 弹簧物理）

**摘要**：扫描分类过程中，一叠拍立得风格卡片持续旋转换位，下方状态文案同步变化。用「纸质卡片在洗牌」隐喻占用等待时间，把不确定的后台排序变成可感知的进度氛围。

**详细展开**  
- **背景与问题**：相册/挑图类任务的扫描阶段常是空白转圈，用户难以判断系统是否在工作、还要多久。  
- **主要功能/观点**：卡堆循环 shuffle 提供持续运动线索；文案承担精确状态；弹簧物理让换位不显生硬。标签含 Card Stack / Loading / Spring Physics / Skeuomorphic。  
- **对快速掌握移动端动效的启示**：loading 动效要回答「还活着吗」而非「好看吗」——循环运动 + 可变文案比单一 spinner 更耐等。设定最长循环与完成后的 settle（卡堆停稳 → 结果列表），避免扫完仍在洗牌。无障碍：提供进度百分比或「已处理 n/N」；Reduce Motion 时停 shuffle，只留文案与确定进度。证据层级为动效展示，非实验室等待容忍实验。  
- **原文链接**：https://60fps.design/shots/picky-card-scan-sort-interaction

### [Don’t Outsource the Learning: Why Human-Led Research Still Matters in the Age of AI]
**来源**：Nielsen Norman Group（2026-07-17；专家相关：Kate Moran 所在机构 NN/g）  
**类型**：专家观点/动态  
**是否与动效相关**：否（用研方法论：团队学习不可外包；可间接约束「只看 AI 报告做动效决策」）

**摘要**：NN/g 论证：即便未来 AI 产出的报告质量追上资深研究员，人类主导研究仍不可替代——因为研究交付的不只是 findings，还有团队共同见证用户故事后的学习、共情与行动动机。提出用「做这件事能否让团队学到东西」检验哪些环节可交给 AI。

**详细展开**  
- **背景与问题**：组织容易把用研看成「出洞察报告」的专项，于是 AI 模拟用户、代访谈、代编码显得很有吸引力。  
- **主要观点**：研究有双产出——可交付物 vs 参与者学习体验；故事比技术说明更能调动注意、共享理解与行动（文中引用神经与行为研究）。保护主持、现场观察、共同复盘与意义建构；招聘排期、转写、初稿整理等可交给 AI。警惕「读完报告就以为学会了」的学习错觉。  
- **对移动端用研或 AI 产品经理的启示**：动效/微交互评审不要只消费 AI 汇总的「用户觉得很丝滑」——至少保留一小段团队共看原始任务录像（跟手延迟、误触、前庭不适）。把 AI 用于剪辑高亮与初码，把「是否砍掉这段运动」的判断留在人的复盘会上。  
- **原文链接**：https://www.nngroup.com/articles/human-led-research-still-matters/

### [AI持续学习火了：下一代智能体拼的不是“会回答”，而是“会积累”]
**来源**：人人都是产品经理 / AI阿铭（2026-08-03；专家相关：AI 产品经理常驻平台）  
**类型**：专家观点/动态  
**是否与动效相关**：否（记忆治理与长期协作；与过程状态可见性相邻）

**摘要**：文章区分参数学习、外部记忆与流程学习三层，强调面向用户的「持续学习」首先是上下文/记忆/反馈管理，而非模型偷偷自训。给出捕捉—筛选—固化—调用—遗忘闭环，以及身份/项目/流程/反思四层记忆法，并提醒错误记忆固化与隐私冒犯风险。可与本期 MSR CTEM 对照阅读。

**详细展开**  
- **背景与问题**：AI 使用从短问短答走向长期协作后，「每天像第一天上班」成为硬伤；主流助手都在加个人/项目记忆。  
- **主要观点**：好记忆系统要回答记什么、何时忘、谁可看、如何证明仍可信；企业场景还需客户隔离与审计。评估应看补充背景次数、引用准确率、错误记忆可删性、隔离是否生效，而非只看「更懂我」的情绪分。  
- **对移动端用研或 AI 产品经理的启示**：移动 Agent 设置页应用研「记忆可见性」——用户能否在 30 秒内找到并删除一条会改变行为的记忆。状态表达上，当 AI 说「我记得你上次…」时应提供来源入口，避免只靠拟人微动效制造亲密感。可与 CTEM 的情绪—行为闭环一起设计：哪些更新需用户确认拍。  
- **原文链接**：https://www.woshipm.com/ai/6438276.html

### [Xiaomi HyperOS 3 or iOS 26? Spot the difference (if you can)]
**来源**：Gizchina（2026-01-25）  
**类型**：移动设备竞品分析  
**是否与动效相关**：是（Liquid Glass 模糊 / 灵动岛式气泡伸缩 / Face Unlock 环形波形）

**摘要**：媒体侧对比指出 HyperOS 3 在半透明玻璃、通知岛气泡、图标圆角配色乃至 Face Unlock 波形动效上高度贴近 iOS 26 方向。对动效用研的价值是：把「系统级签名运动」列成可对拍清单（解锁波、岛扩展、控制中心滑块），而不是只谈整体「像不像」。

**详细展开**  
- **背景与问题**：跨品牌系统体验讨论常停在「抄袭/致敬」情绪，缺少可复现的动效观察点。  
- **主要发现/观点**：文中点名 launcher/相册的液态模糊、通话/音乐岛的扩展动画、天气/电话/信息图标样式，以及 Face Unlock 由旧视觉改为接近 Face ID 的环形波。作者将其解释为让中端硬件获得「高端观感」的策略。  
- **启示（含动效）**：竞品协议可固定拍摄：解锁波形时长与圈数、岛从紧凑到展开的 easing、控制中心滑块跟手。区分「视觉相似」与「输入—首帧位移」两套指标，避免被美学相似度掩盖跟手差距。证据层级为媒体观察与早期泄漏对照，非实验室 FPS；结论需用可复现机位复测。  
- **原文链接**：https://www.gizchina.com/xiaomi-phones/xiaomi-hyperos-3-or-ios-26-spot-the-difference-if-you-can
