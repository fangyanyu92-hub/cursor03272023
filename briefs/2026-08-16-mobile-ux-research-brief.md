### LookAgain：把 GUI 坐标当作「可再看一眼」的假设，而不是一次拍板
**来源**：哈尔滨工业大学（深圳）/ 北京邮电大学 / 深圳环区研究院 / 上海财经大学；arXiv 2608.09723（Renshan Zhang, Haoyang Meng, Yixiao He, Rui Shao, April Hua Liu, Liqiang Nie）  
**类型**：方法论  
**是否与动效相关**：是（视觉标记 / 局部高清回看 / 闭环核验反馈）

**摘要**：LookAgain 把 GUI grounding 从「一次回归出坐标」改写成 predict–look-again–refine：模型先投下坐标假设，再在该位置渲染 marker 并裁出高清局部图，决定确认或改点。LookAgain-8B 在 OSWorld-G 达到 73.0（较 Qwen3-VL-8B 基座 +21.7），UIVision / ScreenSpot-Pro 分别 +15.5 / +13.1。对动效学习的价值是：核验不该只靠文字自评，而要把「我点了哪里」做成可见、可回看的运动/视觉证据。

**详细展开**  
- **背景与问题**：SeeClick、OS-Atlas、UI-TARS 等单次 grounding 在标准集上已明显进步，但在小目标、密控件和 OOD 界面上仍会陡降，并成为下游 Agent 级联失败的主因。现有补强要么在出坐标前加推理/注意力，要么做 iterative zoom-in 去 refinement「视野」，都没有把已经产出的坐标当作可被新视觉证据推翻的假设。  
- **主要发现/方法/功能/观点**：作者归纳三个耦合缺口——缺事后反思、视觉证据与最终预测脱节、 refinement 作用在视图而非预测。LookAgain 用两个原语闭环：`locate` 发布坐标、打标、追加局部高清 patch；`confirm` 接受或拒绝并终止。训练是两段式：先在构造的多轮反思轨迹上做 SFT 冷启动，再用 GRPO、仅以终止步 grounding 对错为奖励，促使模型「该改才改、已准就停」。  
- **对移动端用研或 AI 产品经理的启示（含动效）**：评测 Agent 不要只报最终点击对错，应拆「假设—回看—改点—确认」四段，并统计小目标/密布局上的改点次数。落地动效可把核验做成设计 token：定位用短促高对比 marker（快节奏），确认用稳定收束（慢节奏）；次要区域不做同等强度闪烁，避免把「我在检查」做成全屏干扰。Reduce Motion 下应用静态高亮框替代脉冲。  
- **原文链接**：https://arxiv.org/abs/2608.09723（镜像：https://arxiv.org/html/2608.09723 ；实现：https://github.com/iLearn-Lab/LookAgain）

### SketchDynamics：自由草图如何向生成模型说清「怎么动」
**来源**：香港科技大学 / 港科广；CHI 2026（Boyu Li, Lin-Ping Yuan, Zeyu Wang, Hongbo Fu）  
**类型**：方法论  
**是否与动效相关**：是（动效意图表达 / 分镜→运动图形 / 澄清与逐帧改动）

**摘要**：CHI 2026 论文指出，现有草图动画系统常把笔触收成固定命令 token，丢掉了草图的开放表达力。SketchDynamics 让用户用自由分镜向视觉—语言模型传达动态意图，并经 24 人三阶段研究证明：少量笔触就能传达运动，但歧义必须由人介入澄清，草图还能视觉引导成片修订。对掌握移动端动效的借鉴是：先用「路径 / 节奏 / 次数」把意图外化，再谈工具导出。

**详细展开**  
- **背景与问题**：分镜与箭头、虚线、速度曲线本是动画师表达时间与空间变化的日常语言；生成模型却常把草图当成静态布局或预定义指令，使草图从开放创作媒介退化成控制符。  
- **主要发现/方法/功能/观点**：系统走「草图分镜 → 运动图形」工作流，强调解释类 motion graphics 的运动清晰度优先于写实。三阶段研究（n=24）分别观察：最少输入如何传达运动；箭头既可能是平移也可能是旋转等歧义，需自适应澄清（选项、补资产、延迟与否）；成片不符预期时，用关键帧提取 + 标注（如「黄灯闪两次」、手绘速度—时间曲线）做迭代。作者并讨论向 3D 动画与视频生成迁移。  
- **对移动端用研或 AI 产品经理的启示（含动效）**：写动效 PRD 时不要只写「活泼一点」，应要求路径、次数、快/慢段和可澄清点（与 LookAgain 的「假设可被推翻」同一逻辑）。用研可把「歧义澄清轮次」和「成片一次通过率」当作动效协作指标。移动端落地时，把澄清 UI 做成轻量 chip / 速度曲线，而不是再开一轮自然语言对答。  
- **原文链接**：https://arxiv.org/abs/2601.20622（CHI 节目单：https://programs.sigchi.org/chi/2026/program/content/222469 ；DOI：https://doi.org/10.1145/3772318.3791071）

### AgentLens：移动 GUI Agent 不该只有「全屏直播」或「后台哑巴」
**来源**：成均馆大学（SKKU）；UIST 2026 投稿 / arXiv 2604.20279（Jeonghyeon Kim, Byeongjun Joung, Junwon Lee, Joohyung Lee, Taehoon Min, Sunjae Lee）  
**类型**：方法论  
**是否与动效相关**：是（即时覆盖层 / 全屏·局部·GenUI 切态）

**摘要**：AgentLens 用形成性研究说明：用户要的是「后台执行 + 关键时刻才露脸」，但露脸的视觉模态必须随任务变。系统在 Full UI / Partial UI / GenUI 之间自适应切换；21 人对照实验中 85.7% 选它作日常首选，PSSUQ Overall 1.94，采纳意向 6.43/7。对动效的借鉴是：Agent 进度不应永远全屏播放，而应按风险切换「局部高亮 / 生成摘要卡 / 完整真界面」。

**详细展开**  
- **背景与问题**：移动 GUI Agent 研究长期堆感知与任务成功率，很少问「委派之后怎么给人看」。现有两极是：前台逐步直播（透明但无法并行）与后台纯语音/文本（可并行但失去处境觉察）。GenUI 看似折中，形成性研究里用户却担心价格、支付、菜单被幻觉。  
- **主要发现/方法/功能/观点**：设计空间被收成三种模态——Full UI 用于结账等需空间上下文的高风险核验；Partial UI 只裁真实 App 相关区域，保真且少打扰；GenUI 用于低风险、需重排的简短交互。实现上扩展 `speak` / `ask` 动作，并借 Android Virtual Display 在不可见表面跑第三方 App，再把裁切区域镜像到伴生 App 浮层。对照前台-only 与后台-only，AgentLens 在可用性与采纳上全面更好。  
- **对移动端用研或 AI 产品经理的启示（含动效）**：AX 评测应同时测「能否并行」和「关键步是否看得到真界面」，不要用单一透明度分数。动效 token 建议：低风险 GenUI 用短淡入卡片；Partial UI 用裁切框 + 轻脉冲指向操作区；Full UI 用明确模态进入（慢、可撤销）。高风险步禁止只用生成界面代替真界面——这是信任设计，不是视觉风格。  
- **原文链接**：https://arxiv.org/abs/2604.20279（HTML：https://arxiv.org/html/2604.20279v1）

### UI 动画正在变成可计量的体验基建，而不只是「好看」
**来源**：SoftwareEggs / Ryan Cooper（2026-08-08）  
**类型**：行业报告  
**是否与动效相关**：是（动效趋势 / 微交互与留存口径）

**摘要**：这篇 8 月 8 日综述把 UI 动画写成可计量的体验基建：降低认知负荷、即时反馈、导航引导、系统状态与情感连接，并引用 UI 服务市场向 2035 年约 610 亿美元、CAGR 9.22% 的增长叙事。对掌握移动端动效的价值是：把「帧预算、Reduce Motion、任务完成时间」写进同一张趋势表，而不是只收集灵感站。

**详细展开**  
- **背景与问题**：团队仍常把动画当装饰；同时市场上充斥把「设计决定 94% 第一印象」等旧口径反复引用的趋势文，口径需要打折看。  
- **主要发现/方法/功能/观点**：文章归纳 2026 方向为 AI 自适应布局、克制极简、无障碍优先、token 化设计系统、功能性微交互与移动优先。它转述 Toptal 2026「更丰富动画带来约 15% 更高参与」、McKinsey 2026「含 3D 元素的应用会话时长约 +22%」等数字——**这些应视为二手市场叙事，不能当作本团队的因果证据**。更可执行的部分是：动画要能对应认知负荷、WCAG 2.2 与转化，而不是视觉新鲜感。  
- **对移动端用研或 AI 产品经理的启示（含动效）**：做行业对标时，把「动画有/无」改成可复现指标：主路径 FPS、低端机掉帧、Reduce Motion 覆盖率、关键 CTA 入场是否挡住文案（可与 NN/g CTA 公式对照）。用研实验应自建 A/B，而不是引用综述里的 15%/22%。  
- **原文链接**：https://softwareeggs.com/how-ui-animation-improves-user-experience-in-apps-and-software/

### Figma Motion 并不取代 Rive / Lottie / Jitter：按「动画最终要去哪」选工具
**来源**：Beryl Design / Guillaume Hambourger（ATECNA）；2026-07-19  
**类型**：工具  
**是否与动效相关**：是（动效工具对照 / 状态机 vs 时间线 / 导出链路）

**摘要**：Config 2026 之后，Figma Motion 让关键帧留在画布内，但对照实验（Weather Buddy 同项目）表明它仍是「增强版时间线」，不是交互引擎。决策规则：文件内微交互用 Figma Motion，数据驱动/状态机用 Rive，营销短视频用 Jitter，跨端轻量上线用 Lottie。对快速掌握移动端动效的借鉴是：先问「播完即走，还是要跟手/跟数据」，再选工具。

**详细展开**  
- **背景与问题**：团队容易把「Figma 也能做动画了」理解成可以卸载 Rive 或 Lottie 插件；真正卡点是动画离开设计文件之后还要不要响应状态。  
- **主要发现/方法/功能/观点**：Figma Motion 单时间线、XY 默认绑定、适合微交互与转场；AI 可从一句话草拟关键帧，但时间线组织偏乱。Rive 原生分轴、并行动画与 State Machine，并能用数据绑定（如温度 105° 立刻改界面）；眼镜反光等遮罩在 Figma 要复制编组，Rive 更原生。Jitter 走浏览器、快速出 MP4/GIF。Lottie 是 JSON/dotLottie 格式而非编辑器；Figma Motion 尚无原生 Lottie 导出，需社区插件。  
- **对移动端用研或 AI 产品经理的启示（含动效）**：把动效交付分成四格：规格（Figma Motion）/ 状态组件（Rive）/ 宣发（Jitter）/ 生产播放（Lottie）。验收清单应写「是否响应指针/数据」「包体与运行时」「Reduce Motion 回退」。不要用同一套弹性曲线同时服务 onboarding 插画和可点按钮。  
- **原文链接**：https://www.beryldesign.fr/en/post/figma-motion-vs-rive-jitter-lottie

### FocusFlight：主视觉先入场，文案与 CTA 再错落跟上
**来源**：60fps.design / FocusFlight（页面标注 2026-08-10）  
**类型**：案例研究  
**是否与动效相关**：是（onboarding 错落编排 / 地图昼夜过渡 / 弹簧沉降）

**摘要**：FocusFlight 的多步 onboarding 让飞机舷窗视频、平移地图、立体拼图或版本徽章先入场，标题与主按钮再上滑淡入；第二屏地图从日到夜切换，飞机图标沿航线移动，整体用轻弹簧沉降。对掌握移动端动效的借鉴是：信息层级可以用「主视觉 → 文案 → CTA」的时间差来做，而不必加更多装饰层。

**详细展开**  
- **背景与问题**：功能介绍页若所有元素同时弹出，用户分不清先看哪；若每步都做重 3D，低端机与 Reduce Motion 用户会先感到累。  
- **主要发现/方法/功能/观点**：该镜头把 stagger 写成可复用句式：主视觉建立场景，文案解释，CTA 最后激活。日夜主题切换绑在同一地图层上，用航线运动把「时间在流逝」做成连续空间，而不是硬切下一张静图。  
- **对移动端用研或 AI 产品经理的启示（含动效）**：可用性测试可加眼动或首次注视：主视觉是否在 300ms 内被看到、CTA 是否在文案可读之后才抢注意。设计 token：入场 200–350ms spring、CTA 再延迟一拍；Reduce Motion 改为瞬间换图 + 静态航线。对比上期 PhonePe 卡片组装，这里更适合「内容叙事型」onboarding，不适合支付仪表盘信息密度。  
- **原文链接**：https://60fps.design/shots/focusflight-animated-text-and-video-background-onboarding

### 一条好看的 AI 输出是例子，不是评估（专家相关：NN/g）
**来源**：Nielsen Norman Group / Raluca Budiu（2026-08-14）；Kate Moran 所在机构近期方法论  
**类型**：专家观点/动态  
**是否与动效相关**：否

**摘要**：NN/g 在 8 月 14 日指出：对非确定性系统跑一次就下结论，是把确定性软件的习惯误用到 AI。合格评估要像定量 UX 研究：多样且有代表性的输入、同一输入重复跑、报告均值与置信区间，并分开看「题间差异」和「同题多次差异」。

**详细展开**  
- **背景与问题**：客服型 AI 对同一退货问题可能一次讲对政策、一次漏例外、一次承诺不该退的款；团队却常因一次成功 demo 就决定上线。  
- **主要发现/方法/功能/观点**：文章用结账可用性基准做类比：不会让一名用户做一次结账就宣布体验完美。评估至少回答两问——在用户会问的问题范围内表现如何，以及同一问题是否稳定。两个同为 80% 成功的系统可能完全不同：一个稳定死在两类题，一个每题都偶尔翻车；路由到人工还是人工复核草稿，取决于失败如何分布。QA 对 AI 应跟踪重复跑的通过率，而不是单次绿灯。  
- **对移动端用研或 AI 产品经理的启示**：移动 Agent / 语音助手验收应写清：代表任务集、每题重复次数、可接受答案标准（正确、含例外、下一步）。演示动效或一次「点对了」不能代替 LookAgain 式的小目标压力集。若重复跑成本高到做不起，应诚实写「证据不足」，而不是用一条成片当因果。  
- **原文链接**：https://www.nngroup.com/articles/eval-ai-output/

### DeepSeek Harness 实测：能干活，但得盯着（专家相关：人人都是产品经理）
**来源**：人人都是产品经理（2026-08-14 前后；黄钊 / AI 产品经理大本营常驻平台）  
**类型**：专家观点/动态  
**是否与动效相关**：部分（长任务状态与失败可见性）

**摘要**：平台对 8 月 13 日晚发布的 DeepSeek Harness（DSH，「一切皆插件」）做了接入 V4-Pro、思考档 High 的实操评测：简单任务能完成，复杂任务纠错后完成度尚可，但长任务、并行与工具配置仍不稳。作者明确写明「各项结果均为单次生成，存在随机性」——正好可与本期 NN/g「一条输出不是评估」对读。

**详细展开**  
- **背景与问题**：Harness 上线约 12 小时 GitHub Star 破 5 万，产品叙事从「提供模型」转向「把模型、工具、Skills 拆装成可执行环境」，普通用户门槛也被一并抬高。  
- **主要发现/方法/功能/观点**：评测未集邮式覆盖全部模式，标准模式下简单任务可用，复杂任务需要人盯；插件/创造模式提供常规 Agent 少见的玩法，但对工具配置敏感。平台同时出现 GLM-5.3、Grok 4.6 等同日竞争稿，共同信号是：竞争从「对话分数」转向「长程能否一次交付」。  
- **对移动端用研或 AI 产品经理的启示（含动效）**：移动端 Agent 若复用「可插拔工具」架构，要用研先定义哪些插件允许自动跑、哪些必须停在确认步（呼应 AgentLens 的 Full UI 核验）。状态动效应区分「插件加载 / 并行分叉 / 失败可重试」，避免一条无限进度条。把「单次实测」标成探索，把重复跑与失败分布做成正式评测——不要用 Star 数代替任务成功率。  
- **原文链接**：https://www.woshipm.com/ai/6447663.html

### 小米 HyperOS 4：Soft Light Glass 先上旗舰，玻璃动效被写成性能分层
**来源**：GSMArena；Nokiamob / YTECHB 等同步报道（发布约 2026-08-13，中国区公测首批 2026-08-14）  
**类型**：移动设备竞品分析  
**是否与动效相关**：是（Soft Light Glass / 折射与转场 / 超级岛思考态）

**摘要**：小米把 HyperOS 4 从 Android 17 的 HyperOS 3 更新中拆出，主视觉改走 Soft Light Glass（半透明、软反射、自适应透明度，并强调真实感折射）。中国区 Beta 8 月 14 日起分三批；完整玻璃效果先限骁龙 8 Elite / 天玑 9500 / 玄戒 O1 及以上。可与上期 ColorOS 17「Liquid Acrylic、弱折射换续航与可读」对读：安卓皮肤在学 Apple Liquid Glass，但开始用芯片档位管理动效成本。

**详细展开**  
- **背景与问题**：Android 17 已随 HyperOS 3 推送，但大改版被留到 HyperOS 4。行业同时出现 iOS Liquid Glass 可读性质疑、OPPO Liquid Acrylic 主动降折射、Google 公开拒绝 Pixel 上 Liquid Glass。  
- **主要发现/方法/功能/观点**：锁屏时钟与通知可重排，文件夹/小组件可缩放，浮窗随横竖屏旋转。官方内部口径：使用 9 小时后应用启动约比 HyperOS 3 快 18%；HDR 处理 310ms→240ms，相机冷启动少 200ms。Super AI Assistant 2.0（MiMo）在复杂请求时先用 Super Island 显示「听到了/正在想」，有答案再全屏；Inspiration Ball 可拖到地址/商品再语音执行（全球版可能与 Circle to Search 重叠）。完整 Soft Light Glass 在 Beta 阶段不做全机型齐活。  
- **对移动端用研或 AI 产品经理的启示（含动效）**：竞品动效测试必须按芯片档分层：旗舰看折射与岛动画是否挡字，中端看降级后是否还保留层级（模糊/描边/静态玻璃）。用研任务建议包括：通知堆叠可读、控制中心对比度、Reduce Transparency 等价开关、Agent「思考中」岛动画是否让人误以为系统卡死。不要把「看起来像 iOS」当成可用性结论。
