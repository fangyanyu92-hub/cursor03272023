### [Spatula: Exploring On-Demand In-Situ Interfaces and Interaction for Attribute Control]
**来源**：arXiv / HKUST & HKUST(GZ) & University of Utah（Boyu Li 等；Submitted 2026-07-11）  
**类型**：方法论  
**是否与动效相关**：是（motion graphics 参数微调 / 原位控件 / 弹性属性控制空间）

**摘要**：面向生成式动效精修「改不准、改不动」的痛点，Spatula 把属性控制重新框成可探索的 Elastic Attribute Control Space，并在画布上按需生成原位控件；12 人研究显示其比侧栏/纯提示更能支持细粒度运动参数调节。

**详细展开**  
- 背景与问题：LLM 生成降低了出稿门槛，但「再快一点 / 再弹一点」类文本精修不可预测；传统分层参数面板精确却认知负担高，侧栏 on-demand 控件又脱离视觉上下文。  
- 主要发现/方法/功能/观点：以 motion graphics 为探针场景，归纳四维控制脚手架——Discoverability（情境化原位提示）、Resolution（多精度调节）、Scope（语义联动批量改）、Expandability（主动扩展可用属性）；系统分析动画上下文后把 slider / drag handle 等直接嵌到画布。  
- 对移动端用研或 AI 产品经理的启示；对快速掌握移动端动效：评审与落地时可把「spring / duration / delay / opacity」拆成可发现、可调精度、可批量作用域的 motion token 表，并要求原型工具在元素旁暴露控件，而不是只在 Design Spec 侧栏写数字。  
- **原文链接**：https://arxiv.org/abs/2607.10405（HTML：https://arxiv.org/html/2607.10405v1）

### [GhostUI: Unveiling Hidden Interactions in Mobile UI]
**来源**：ACM CHI 2026 / Seoul National University（Minkyu Kweon 等）  
**类型**：方法论  
**是否与动效相关**：是（隐藏手势 / 微交互可发现性 / 前后态 UI 过渡）

**摘要**：CHI 2026 论文提出 GhostUI：覆盖 81 款热门 App、1,970 条「无可见 affordance 的隐藏手势」多模态数据集（截图 + 视图层级 + 手势元数据 + 任务描述）；微调后的 VLM 在隐藏交互预测与 UI 过渡预测上显著优于基线。

**详细展开**  
- 背景与问题：长按、双击、边缘滑、捏合等大量能力没有视觉线索；用户与 GUI Agent 都难发现，现有数据集又偏「看得见的按钮」。  
- 主要发现/方法/功能/观点：自动化 probing + 人工校验得到六类手势上的隐藏交互；约 23.7% 验证交互属隐藏类，其中 37.7% 依赖现有 Agent 框架很少支持的手势；实验同时评「该点哪里、用什么手势」与「手势后界面会变成什么」。  
- 对移动端用研或 AI 产品经理的启示；对快速掌握移动端动效：隐藏能力若必须保留，应用短促、可中断的 motion/haptic coachmark（按下态形变、边缘 glow、松手回弹）把「可发现性」做成可测指标；Agent 产品则需把「前后态过渡理解」纳入评测，而非只测静态截图标点。  
- **原文链接**：https://dl.acm.org/doi/10.1145/3772318.3790283（CHI 日程：https://programs.sigchi.org/chi/2026/program/content/222920 ；预印本：https://arxiv.org/abs/2601.19258）

### [Usability Hasn’t Peaked: Exploring How Expressive Design Overcomes the Usability Plateau]（往期精选）
**来源**：Google Research / CHI 2026（Alyssa Sheehan, Ying Wang, Bianca Gallardo, Lennard Schmidt, Frank Bentley）  
**类型**：方法论  
**是否与动效相关**：是（表达性设计 / 颜色·形状·尺寸·运动协同 / Material 3 Expressive）  
**首次收录日期**：2026-07-13  

**摘要**：往期精选。48 人 × 10 App 眼动与任务实验显示：遵循 Material 3 Expressive 的界面相对既有 Material，正确元素注视快 33%、任务完成快 20%，且审美评价更高——反驳「移动可用性已到天花板」。

**详细展开**  
- 背景与问题：业界常假设移动 UI 可用性已趋同，新增视觉表达可能损害效率。  
- 主要发现/方法/功能/观点：表达性设计回到 size / shape / color / type / motion / containment 等基本变量，用对比与层级把关键动作推到前台；对 45+ 用户改善往往更大。  
- **本次新增启发角度**：对照本期 GhostUI——表达性运动不只是「更好看」，更可充当隐藏手势的可感知线索（按压缩放、边缘高亮、长按进度环）；对照 Spatula——把「快/慢、弹/稳」落成可原位调节的 motion token，才能把研究里的层级优势复用到跨 App 设计系统。  
- **原文链接**：https://research.google/pubs/usability-hasnt-peaked-exploring-how-expressive-design-overcomes-the-usability-plateau/（ACM：https://dl.acm.org/doi/10.1145/3772318.3790373）

### [Cosmos No Internet Spot Illustration Animation]
**来源**：60fps.design / Cosmos  
**类型**：案例研究  
**是否与动效相关**：是（Empty State / Idle / Orbit 物理感循环）

**摘要**：离线空态用中心球体 + 卫星点轨道循环，以轻量重力感 idle 动效降低「断网」焦虑，示范错误/空状态也可以用克制运动传递品牌气质。

**详细展开**  
- 背景与问题：No Internet 页若只有静态插画或刺耳报错，易放大挫败感。  
- 主要发现/方法/功能/观点：持续低幅 orbit/bob 形成可忽略但仍「活着」的反馈，把等待/重试心智从故障感转为系统仍在呼吸。  
- 对移动端用研或 AI 产品经理的启示；对快速掌握移动端动效：为空态单独设 `idle.orbit` token（低 stiff、可循环、可 `prefers-reduced-motion` 降级为静态），并在可用性测试中问「是否感觉系统卡死」而非只测文案可读。  
- **原文链接**：https://60fps.design/shots/cosmos-no-internet-spot-illustration-animation

### [Duolingo Score Increased Mascot Animation]
**来源**：60fps.design / Duolingo  
**类型**：案例研究  
**是否与动效相关**：是（Reward / Counter / Spring / Stagger / Success State）

**摘要**：课时结束后的加分庆祝：Duo 穿过云层收集金币、撞徽章触发 spotlight，再衔接到分数卡进度填充与 5→6 计数，用多阶段物理动效把「升级」做成可感知的奖励叙事。

**详细展开**  
- 背景与问题：学习产品的分数变化若只改数字，激励与完成感偏弱。  
- 主要发现/方法/功能/观点：角色飞行收集 → 徽章高光 → 进度条/计数器 → idle bob + CTA 淡入，形成「叙事段—结果段—行动段」时间线；bounce/spring 用于奖励峰值，淡入用于收束。  
- 对移动端用研或 AI 产品经理的启示；对快速掌握移动端动效：奖励动效应可跳过且总时长可控；用研可测「用户是否在 CTA 出现前已理解分数变化」，避免庆祝序列挡住下一步。  
- **原文链接**：https://60fps.design/shots/duolingo-score-increased-mascot-animation

### [Liquid Glass vs Material Expressive: 2026 Comparison]（往期精选）
**来源**：Mantlr  
**类型**：移动设备竞品分析  
**是否与动效相关**：是（Liquid Glass 深度折射 vs M3 Expressive 弹簧运动语言）  
**首次收录日期**：2026-07-12  

**摘要**：往期精选。横评 Apple Liquid Glass 与 Google Material 3 Expressive：前者押注空间深度与跨设备材质统一，后者押注情绪化表达与弹簧物理动效，并引用 Google 万级样本研究中「关键元素识别最高约 4× 更快」等结论。

**详细展开**  
- 背景与问题：2014–2024 扁平收敛结束后，两大系统在 2025–2026 分叉加剧，跨端「一套视觉走天下」失效。  
- 主要发现/方法/功能/观点：对比运动、色彩、形状、字体与无障碍策略；Expressive 以 spring + shape morph 做交互语法，Liquid Glass 以折射/层叠做感官深度；第三方采用节奏与无障碍争议并存。  
- **本次新增启发角度**：结合本期 Spatula——跨端竞品拆解不要只截静态，而要记录「空间属性 vs 效果属性」两套 token（位移/缩放 spring 与透明度 tween）是否可被设计师原位调参；结合 GhostUI——评测隐藏手势时分别在两套系统上测 coachmark 可发现性。  
- **原文链接**：https://mantlr.com/blog/liquid-glass-vs-material-expressive

### [A Concrete Definition of “Product Sense” (and How to Build It)]
**来源**：Nielsen Norman Group（专家相关：Kate Moran 所在机构 NN/g；2026-07-24）  
**类型**：专家观点/动态  
**是否与动效相关**：否（可延伸：把动效 A/B 结果纳入个人决策经验库）

**摘要**：NN/g 于 2026-07-24 将「product sense」重定义为：识别当前问题与过往成败模式的相似处，并可靠预估同类方案结果——关键是跑完「面对问题→选型→测结果→反思」闭环，并知道何时模式不适用。

**详细展开**  
- 背景与问题：AI 接手大量执行工作后，「该做什么」压力上升，但既有 product sense 定义偏「共情+创意」，难训练、难度量。  
- 主要发现/方法/功能/观点：区分高效度 / 低效度 / wicked 情境；强调留下看结果，避免只做半截交付；输入堆砌（拆竞品、读评测）不足以形成判断力。  
- 对移动端用研或 AI 产品经理的启示：把动效决策也纳入闭环——每次上线记录「用了哪组 spring/时长、任务时延/抱怨率如何」，形成可复用的个人模式库；在 Agent/新范式（低效度）场景主动降级直觉、加强实验。  
- **原文链接**：https://www.nngroup.com/articles/product-sense-definition/
