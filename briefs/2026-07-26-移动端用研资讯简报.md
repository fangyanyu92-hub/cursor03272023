### [SketchDynamics: Exploring Free-Form Sketches for Dynamic Intent Expression in Animation Generation]
**来源**：ACM CHI 2026 / HKUST（Boyu Li, Lin-Ping Yuan, Zeyu Wang, Hongbo Fu）  
**类型**：方法论  
**是否与动效相关**：是（动画意图表达 / 草图驱动 motion graphics / 人机共释）

**摘要**：CHI 2026 论文提出以自由草图故事板向 VLM 表达「动态意图」，并经三阶段、24 人研究证明：草图能以极少输入传达运动，但歧义需澄清回路与帧上 refinement 才能落地为可控动画。

**详细展开**  
- 背景与问题：既有草图动画系统常把笔迹绑成固定命令 token（箭头=平移等），牺牲了自由表达；纯生成又难对齐「怎么动、何时动」。  
- 主要发现/方法/功能/观点：SketchDynamics 把草图当开放语义提示，配合自适应 clarification cue 与生成结果上的视觉编辑（如速度—时间曲线）；研究显示歧义可被转化为意图细化资源，而非仅靠收紧手势词表。  
- 对移动端用研或 AI 产品经理的启示；对快速掌握移动端动效：可用「草图故事板 → 澄清问题 → 帧上改动」做动效评审协议——先让干系人画出关键路径/节奏，再把歧义类型（平移 vs 旋转、延迟 vs 同步）做成检查清单，再落到 spring / duration token。  
- **原文链接**：https://dl.acm.org/doi/10.1145/3772318.3791071（镜像：https://programs.sigchi.org/chi/2026/program/content/222469 ；预印本：https://arxiv.org/html/2601.20622）

### [Notational Animating: An Interactive Approach to Creating and Editing Animation Keyframes]
**来源**：ACM CHI 2026  
**类型**：方法论  
**是否与动效相关**：是（关键帧创作 / 运动符号形式化 / 参数化微调）

**摘要**：另一篇 CHI 2026 动效方法论将动画师草图符号形式化为 source–path–target 结构，用 GenAI 生成关键帧，并以动态 UI 控件闭环消歧；初步用户研究显示其推动「多元素整体编排」而非逐步单点改动。

**详细展开**  
- 背景与问题：专业动画师长期用路径、力、姿态等记号思考运动，但记号语境依赖、组合歧义大，难以被系统稳定解释。  
- 主要发现/方法/功能/观点：作者分析约 135 份真实草图后提出结构化动画表示；系统把高层记号译成意图，再暴露空间范围、强度与时序的直接操纵控件，形成执行鸿沟与评估鸿沟的双向收窄。  
- 对移动端用研或 AI 产品经理的启示；对快速掌握移动端动效：评审微交互时可强制写出「主体 / 路径 / 目标态」三元组（例如：FAB → 弧线展开 → 三个操作项），再补 stiffness/damping 或 duration token——比只说「弹一点」更可测、可复用。  
- **原文链接**：https://dl.acm.org/doi/10.1145/3772318.3790707（镜像：https://programs.sigchi.org/chi/2026/program/content/222027）

### [Sidekick: Designing Communication for Effective Multitasking with Computer Use Agents]
**来源**：UIST ’26（投稿稿）/ arXiv（UMich + Adobe Research；submitted 2026-07-20）  
**类型**：方法论  
**是否与动效相关**：是（ambient 状态色 / 缩略图进度 / GUI 动作高亮与回放）

**摘要**：面向 Computer Use Agents（CUA）多任务协作，Sidekick 在后台用 ambient 线索标进度、在恢复时给多模态摘要、在前台口语+可视化推理；30 人实验显示较聊天式或纯外围文本反馈，更能兼顾主任务并提升进度感知与错误可追溯性。

**详细展开**  
- 背景与问题：CUA 长时自主执行时，反馈多为文本，用户难边干边盯、也难重建「界面上发生了什么」。  
- 主要发现/方法/功能/观点：形成性研究归纳前台/后台沟通缺口；原型用外围色（绿/黄/红）、缩略图与语音摘要、点击/输入标注等跨模态信号；相对「仅聊天文本」与「仅外围文本」基线，次任务成功与干预时机更优且少打断主任务。  
- 对移动端用研或 AI 产品经理的启示；对快速掌握移动端动效：把 Agent 状态做成可扫视的运动语言——后台用低幅 ambient（色相/脉冲，避免抢焦点），恢复时用短序列高亮回放关键 GUI 变化，前台用同步标注；并准备 `prefers-reduced-motion` 下的静态色块+文案降级。  
- **原文链接**：https://arxiv.org/abs/2607.17527（HTML：https://arxiv.org/html/2607.17527）

### [BurnBar Glass Fill Up Animation]
**来源**：60fps.design / BurnBar  
**类型**：案例研究  
**是否与动效相关**：是（Morph / 液体填充 / Spring / Picker 联动）

**摘要**：2026-07-24 收录的健康追踪 App 微交互：底部饮品 carousel 切换时，中央杯型 morph、液面波动填充、计数与进度条同步、火焰 icon bounce，用多通道运动确认「记一笔」动作。

**详细展开**  
- 背景与问题：记饮/计数类高频操作若只有数字跳动，反馈弱、品牌感薄。  
- 主要发现/方法/功能/观点：选择变更同时驱动造型 morph、液量填充、数值 scale、进度与装饰性 bounce，形成「内容态—进度态—情绪态」同帧对齐。  
- 对移动端用研或 AI 产品经理的启示；对快速掌握移动端动效：拆 token——`morph.duration`、`fill.wave`、`counter.spring`、`accent.bounce`；用研可测「用户是否在松手前已理解计数已变更」，避免装饰动效晚于状态提交。  
- **原文链接**：https://60fps.design/shots/burnbar-glass-fill-up-animation

### [Bump Splash]
**来源**：60fps.design / Bump  
**类型**：案例研究  
**是否与动效相关**：是（3D Zoom / Onboarding / Logo Morph / Sequence）

**摘要**：同日（2026-07-24）社交 App 启动序列：从地球 3D 一路 zoom 到街区，叠加头像、距离徽章与反应 icon 的弹性缩放，最后 morph 进脉冲 Logo splash，用连续镜头建立「本地社交」心智。

**详细展开**  
- 背景与问题：位置社交冷启动需在数秒内讲清「附近有谁、为何好玩」，静态 splash 难承载叙事。  
- 主要发现/方法/功能/观点：尺度连续变化（全球→街区）+ 角色元素入场 + Logo 落版，形成单镜头品牌叙事；弹跳缩放用于反应 icon，增强趣味但不阻断主路径。  
- 对移动端用研或 AI 产品经理的启示；对快速掌握移动端动效：Onboarding 可按「空间缩放叙事 → 关键元素 stagger → 品牌落版」三段式计时；务必测首启跳过率与眩晕/晕动投诉，并提供 shortened / reduced-motion 版本。  
- **原文链接**：https://60fps.design/shots/bump-splash

### [Users Say iOS 26 Animations Feel "Stuttery" Compared to Android Rivals]（往期精选）
**来源**：MacObserver  
**类型**：移动设备竞品分析  
**是否与动效相关**：是（系统动画流畅度 / Liquid Glass 负载）  
**首次收录日期**：2026-07-07  

**摘要**：往期精选。用户侧反馈指 iOS 26 部分转场「卡顿/顿挫」，对比部分 Android 旗舰更顺；与视觉特效（如 Liquid Glass）合成负载相关的体验争议仍具对照价值。

**详细展开**  
- 背景与问题：大厂系统动效升级常把「更炫」与「更稳」绑在一起，beta/新系统期易出现帧时间尖峰。  
- 主要发现/方法/功能/观点：报道汇集用户对开闭 App、桌面滑动等场景的主观流畅度对比；需注意其为用户舆情与二手观察，非实验室帧耗时基准。  
- **本次新增启发角度**：结合本期 Sidekick——系统/Agent 反馈动效应分层：表达性运动留给前台关键态，后台与高频导航优先「稳帧 + 可中断」；用研可把「特效开/简」作为可访问性与性能对照条件，而不仅做截图美观对比。  
- **原文链接**：https://www.macobserver.com/news/users-say-ios-26-animations-feel-stuttery-compared-to-android-rivals/

### [UX-Context Design: Using UX Knowledge to Inform AI-Generated Design]
**来源**：Nielsen Norman Group（专家相关：Kate Moran 所在机构 NN/g；2026-07-24）  
**类型**：专家观点/动态  
**是否与动效相关**：否（可延伸：把 motion token 写入 AI 可读上下文）

**摘要**：NN/g 于 2026-07-24 刊文提出「UX-context design」：当界面越来越多由 AI 生成，用研与设计的交付物应从「给人读的文档」转向「给模型用的策展上下文」；并讨论 Google Labs `DESIGN.md` 与假想的 `UX.md`。

**详细展开**  
- 背景与问题：无上下文的 AI 只会产生「平均界面」；组织内非设计师也会用 AI 出 UI，却缺少用户与标准注入。  
- 主要发现/方法/功能/观点：主张策展研究洞见、交互标准、术语表、用户/情境模型为机器可读上下文；以 `DESIGN.md`（视觉 token + 利弊说明）为范例，设想更广的 `UX.md`；成功标准是「生成质量是否提升」而非「汇报是否好看」。  
- 对移动端用研或 AI 产品经理的启示：可把本期 CHI 动效三元组、spring/速度语义、reduced-motion 规则写进仓库旁路的 motion 段，让生成链路默认带上运动规范；用实验对比「有/无 UX 上下文」的任务完成与动效一致性。  
- **原文链接**：https://www.nngroup.com/articles/ux-context-design/
